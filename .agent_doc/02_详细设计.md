# 详细设计 — GrepLogViewer v0.0.7

## 1. 修复 "View container 'panel' does not exist" 警告

### 问题根因
`package.json` 的 `contributes.views` 中包含 `"panel"` 容器：
```json
"panel": [
  { "id": "greplogviewer.timelineView", "name": "Keyword Timeline", "type": "webview" }
]
```
`"panel"` 不是 VS Code 的内置视图容器。内置容器只有 `explorer`、`scm`、`debug`。自定义容器需要通过 `contributes.viewsContainers` 注册。
由于本项目不需要底部分panel，修复方案是将 `timelineView` 移到 `explorer` 容器。

### 修改
```json
// 删除整个 "panel" 键，将 timelineView 合并到 explorer
"views": {
  "explorer": [
    { "id": "greplogviewer.configView", "name": "GrepLogViewer", "type": "webview" },
    { "id": "greplogviewer.timelineView", "name": "Keyword Timeline", "type": "webview" }
  ]
}
```

## 5. 智能时间格式自动检测

### 5.1 检测策略
`TimeMatchModel.autoDetect(lines: string[]): TimePatternConfig | null`

按优先级尝试以下格式模板，每个模板尝试匹配前 5 行，3 行匹配成功则视为检测到：

优先级从高到低：
1. `[YYYY-MM-DD HH:mm:ss.SSS]` — 最常见日志格式
2. `[YY-MM-DD HH:mm:ss.SSS]` — 两位年份
3. `[YYYY-MM-DD HH:mm:ss]` — 无毫秒
4. `[YY-MM-DD HH:mm:ss]` — 两位年份无毫秒
5. `YYYY-MM-DD HH:mm:ss.SSS` — 无方括号
6. `YYYY-MM-DD HH:mm:ss` — 无方括号无毫秒
7. `[s.SSSSSS]` — Linux kernel 风格（可变秒数 + 微秒）
8. `[    s.SSSSSS]` — Linux kernel 风格（固定空格）

### 5.2 自动应用时机
- `ViewController.attach()` 中，若当前编辑器无已保存的 timePattern 配置，则调用 `autoDetect()`
- 检测到格式后自动填充到面板
- 用户仍可手动修改

### 5.3 实现
```typescript
autoDetect(lines: string[]): TimePatternConfig | null {
  const formats = [
    '[YYYY-MM-DD HH:mm:ss.SSS]',
    '[YY-MM-DD HH:mm:ss.SSS]',
    '[YYYY-MM-DD HH:mm:ss]',
    '[YY-MM-DD HH:mm:ss]',
    'YYYY-MM-DD HH:mm:ss.SSS',
    'YYYY-MM-DD HH:mm:ss',
    '[s.SSSSSS]',
    '[    s.SSSSSS]',
  ];
  const sampleLines = lines.slice(0, Math.min(5, lines.length));
  
  for (const format of formats) {
    const segments = this.parseFormat(format);
    let matches = 0;
    for (const line of sampleLines) {
      const result = walkSegments(line, segments, 0);
      if (result) { matches++; }
    }
    if (matches >= Math.min(3, sampleLines.length)) {
      return { format };
    }
  }
  return null;
}
```

## 7. Keyword 匹配范围选择

### 7.1 类型变更
```typescript
interface KeywordConfig {
  // ... 现有字段
  /** 匹配范围：'matched' (仅在已匹配行中匹配) | 'full' (全文扫描) */
  matchScope?: 'matched' | 'full';  // 默认 'matched'
}
```

### 7.2 语义说明
- `'matched'`（默认）：keyword 正则仅在已被 regex groups 匹配的行中进行匹配。未匹配行中的 keyword 不会高亮，也不会被标记为可见。
- `'full'`：keyword 在 [scanStart, scanEnd) 范围内的**所有行**进行匹配。命中 keyword 但未被 group 匹配的行保持可见（当前行为）。

### 7.3 实现变更点

**ViewController.markKeywordVisibleLines()**:
- 新增 `matchScope` 参数传递
- 当 `matchScope === 'matched'` 时：只对 `results` 中 `groupId !== null` 的行执行 keyword 匹配
- 当 `matchScope === 'full'` 时：保持现有行为

**EditorDecorations.apply()**:
- computeKeywordMatches 需要知道每条 keyword 的 matchScope
- `'matched'` 时只扫描 `matchedLineNums` 集合中的行
- `'full'` 时扫描 [scanStart, scanEnd)

**ConfigPanel**:
- 每个 keyword row 新增一个 toggle/select 选择 `matched` 或 `full`
- 默认 `matched`

**FilterResultModel / FilterController**:
- 无需变更，keyword 匹配在 View 层完成

### 7.4 向后兼容
- 未设置 `matchScope` 的关键字默认使用 `'full'`（保持现有行为）
- 与新 UI 创建的 keyword 默认 `'matched'`
